# faq-ai — AI採用システム

会社説明会チャットと AI 面接官。採用業務のうち、一次対応と初期スクリーニングを自動化します。

提案用のデモとして作り始めて、そのまま本番運用できるところまで実装しました。

## 同じコードが2つの姿で動く

デモ版と本番版を別に作ると、片方だけ直して食い違う事故が必ず起きます。なので分けませんでした。

| | デモ | 本番 |
|---|---|---|
| 起動条件 | `index.html` を開くだけ | `DATABASE_URL` を設定 |
| データ保存 | ブラウザの localStorage | PostgreSQL |
| 個別URL | 擬似トークン | 認証付き・期限付き・使い切り |
| 管理画面 | 誰でも開ける | ログイン認証と操作ログ |
| APIキーの置き場所 | サーバーの環境変数 | 同じ |

切り替えの分岐は起動時の1回だけです。デモ専用のコードは持っていません。

デモモードは**外部通信をしません**。定義済みのナレッジから応答します。商談中に会場の Wi-Fi や API の都合で止まらないための保険です。

## 設計で考えたこと

### AIに合否を決めさせない

AI面接官はスコアを出しますが、**合否は人が押します**。完了画面に結果は出しません。

スコアが低くても、回答を読むと独学で Excel マクロを組んで業務を月6日分短縮していた、というような候補者が出てきます。そこで人事が拾える導線を残すことが、このシステムの要件でした。

### APIキーをブラウザに出さない

ブラウザとサーバーの2層構成です。

| 層 | 中身 | 役割 |
|---|---|---|
| ブラウザ | `*.html` / `assets/` | 画面。素の HTML・CSS・JavaScript（フレームワーク無し） |
| サーバー | `api/*.js` | LLM の呼び出し。**APIキーはここだけが持つ** |

キーはサーバーの環境変数にのみ置きます。画面で入力させることもしません。

### ナレッジの定義を1箇所にする

ナレッジ（`assets/js/knowledge.js`）と面接設問（`assets/js/interview-data.js`）は、**ブラウザとサーバーが同じファイルを読みます**。末尾の `module.exports` はブラウザでは実行されません。

定義が2箇所に分かれて片方だけ古くなる事故を防ぐためです。

### 答えるべきでない質問は引き継ぐ

給与の個別交渉や選考状況の問い合わせなど、AIが答えてはいけない質問があります。これを人事へ引き継ぐ経路を、答えられる質問と同じ重さで実装しています。

### フレームワークを使わない

採用担当者が数年後に細かい文言を直したいとき、ビルド環境を用意させずに済ませたかったためです。HTML を開いて直せば、それがそのまま本番です。

## 動かし方

| やりたいこと | 方法 |
|---|---|
| 画面を見るだけ | `index.html` をブラウザで開く（`file://` で可） |
| サーバーも含めて手元で | `npm install` → `vercel dev`（`.env.local` に APIキー） |
| 公開する | Vercel にリポジトリを接続 |

### デモ用の候補者URL

| 候補者 | URL |
|---|---|
| Webエンジニア／中途 | `/interview?token=demo-tanaka` |
| ポテンシャル採用 | `/interview?token=demo-suzuki` |
| カスタマーサポート | `/interview?token=demo-kato` |

存在しないトークンでは「URLが正しくありません」の画面になります。

動画はプレースホルダーです。`briefing.html` の `.player__stage` と `assets/js/briefing.js` の `Player` を `<video>` に差し替える前提で、チャプターの時刻はそのまま `video.currentTime` に対応します。

## 動作確認

`_selftest.html` をブラウザで開くと、4画面を iframe で読み込んで実際に操作し、**72項目**を自動で確認します。結果はページ上とタブのタイトルに出ます。

確認していること（抜粋）:

- チャットが答えるべき質問に正しく答える（6パターン）
- チャットが答えるべきでない質問を人事へ引き継ぐ（4パターン）
- AI面接を6問すべて通し、記録が保存され、**完了画面に合否が出ない**こと
- ダッシュボードで人が合否を押せること、一覧のバッジが連動すること

ナレッジや設問を差し替えたら、このページを開いて全項目が OK になるか確認します。

## データの取り扱い

このリポジトリに登場する会社名・候補者名・回答内容は**すべて架空**です。

- コミットされた APIキー — なし
- メールアドレス — `recruit@example.invalid` のみ（`.invalid` は予約 TLD で実在しません）
- 外部通信先 — LLM の API のみ。CDN・外部フォント・解析タグは一切なし
- 電話番号・住所などの実在情報 — なし

外部依存がないので、デモモードは通信が無くても完全に動作します。
